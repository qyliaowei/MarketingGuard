# 营销雷达·规则库更新工作流
## ——让过滤器跟上不断变身的营销话术

> 营销话术会随平台和 AI 生成技术不断"换皮"，但**变的是名词，不变的是结构**（焦虑-解药、权威背书、收网动作）。
> 因此规则库不需要推翻重来，只需定期"补词、加句式"。本工作流让这件事变成 10 分钟的例行操作。

---

## 一、更新闭环总览

```
① 日常使用 App（自动收集命中样本）
        ↓
② 主界面「导出命中样本」→ 分享/复制
        ↓
③ 把样本交给 AI（本对话即可）→ 归类 + 提取新特征
        ↓
④ AI 产出新版 rules JSON（版本号 + 日期）
        ↓
   ┌────┴─────────────────────┐
   A. 手动路线                B. 订阅路线（推荐）
   导入本地 JSON              提交到 GitHub 仓库
   （立即生效）               → 手机点「检查更新」
   └────┬─────────────────────┘
        ↓
⑤ 主界面核对版本号与来源 → 回到 ①
```

**建议节奏**：每 2 周例行一次；遇到明显的新型话术（新名词、新骗局皮）随时加更。

## 二、App 端自动能力

| 能力 | 说明 |
|---|---|
| 样本自动收集 | 检测到 🟡 以上内容时，自动把文本+等级+得分存入本地 `captured_samples.txt`（超 200KB 自动清空重写） |
| 一键导出样本 | 主界面「导出命中样本」按钮，通过系统分享面板发送，可粘贴给 AI |
| **远程订阅更新** | 主界面填写订阅地址（如 GitHub raw 链接）→「检查更新」，下载校验后立即生效，多设备共用一份规则 |
| 导入本地规则 | 主界面「导入本地规则库」调用系统文件选择器；导入前自动校验，**校验失败不会覆盖旧规则** |
| 三级来源优先级 | **本地导入 > 远程订阅 > 内置规则**，随时可「恢复内置规则」清空外部规则 |
| 版本可视化 | 主界面显示当前规则版本号、更新日期、来源（内置/远程/本地） |
| 即时生效 | 新规则在下次检测时自动加载，无需重启服务或重装 App |

### 订阅地址怎么来（推荐做法）

1. 在 GitHub 建一个仓库（可以是 private，但 raw 链接需可访问；public 最省事）
2. 把 `marketing_filter_rules.json` 放在仓库根目录
3. 订阅地址填：`https://raw.githubusercontent.com/用户名/仓库名/main/marketing_filter_rules.json`
4. 以后 AI 产出的新版 JSON 直接 commit 覆盖该文件 → 手机点「检查更新」即完成升级

> 注意：`raw.githubusercontent.com` 在国内可能访问不稳定，可用 Gitee、jsDelivr CDN 或自己的对象存储；只要是返回 JSON 的直链即可。

## 三、给 AI 的规则扩充请求模板（复制即用）

把导出的样本粘贴进下方模板发给 AI：

```
我有一批手机上检测到的新型营销文案样本，请帮我扩充《营销文案特征数据库》规则库：

【样本列表】
1. （粘贴样本1）
2. （粘贴样本2）
...

请按以下要求处理：
1. 归类：判断每条属于已有类别（焦虑贩卖/成功学权谋/财富诱惑/伪学术/虚构史料）
   还是新类别；新类别请命名
2. 提取特征：每个样本提取高频黑名单名词、伪深刻句式、收网动作、
   所利用的逻辑谬误
3. 去重合并：与现有规则库重复的词条跳过，不要重复计分
4. 产出：完整的 rules JSON（在上一版基础上增补），rules_version 按
   "v1.x-YYYYMMDD" 递增，updated_at 填今天日期
5. 附一段简短说明：本次新增了什么、为什么收录
```

## 四、手动积累样本模板（可选，遇到 App 没检出的漏网话术时用）

| 字段 | 填写说明 | 示例 |
|---|---|---|
| 日期 | 发现日期 | 2026-11-09 |
| 平台 | 抖音/小红书/视频号/公众号… | 抖音 |
| 类型 | 短视频/图文/直播/评论 | 短视频 |
| 原文摘录 | 标题或字幕关键句 | "AI 副业万法，普通人最后的窗口期" |
| 收网动作 | 最后引导做什么 | "点击小风车领取资料包" |
| 漏检原因（猜） | 为什么规则库没报 | "万法"是新名词，"小风车"不在收网正则 |

> 把这张表的内容也发给 AI 处理，重点是第 4、5 行——它们决定要补什么规则。

## 六、防"误伤"机制（扩充规则时必须遵守）

1. **反讽豁免**：规则库有自我指涉词表（营销话术盘点/反诈/辟谣/骗局揭秘等），命中时得分除以 3，防止"讲套路的内容"被误报。
2. **校验优先**：导入时 JSON 合法性和 keywords 字段完整性强校验，坏文件不落盘。
3. **上限计分**：每类关键词最多计 4 个词，防止长文刷分。
4. **人工复核**：AI 产出新规则后，建议先看一眼新增词条是否过于宽泛（如把"赚钱"这种正常词也拉黑），过于宽泛的词降为四星或删除。
5. **白名单扩充**：如果发现正规媒体内容被误报，把来源关键词加入 JSON 的 `whitelist`，并告知 AI 调整。

## 七、后续可扩展方向（按需推进）

- **OCR 补强**：接入 ML Kit 本地文字识别，覆盖无字幕纯画面视频
- **云端订阅**：把 rules JSON 放到 GitHub 仓库，App 定期拉取新版本（需加网络权限，适合多设备同步）
- **样本打标**：App 内长按警示条可标记"误报/漏报"，进一步喂给 AI 优化阈值与权重
